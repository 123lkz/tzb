# Agent 3 设计框架文档

> **所属项目**：多源异构数据驱动岗位和能力图谱构建与动态演化分析研究  
> **所属层级**：AI 智能体分析层（紫色层）  
> **核心职责**：简历解析 + 人岗匹配  
> **依赖**：依赖 Agent2 产出的 `jobs_kg`（岗位-技能关系）和 `nlp_profiles`（岗位画像/技能画像）  
> **复用**：复用 Agent2 的 DeepSeekClient、ProfileStore、数据模型  
> **LLM 通道**：DeepSeek HTTP API（Node.js 桥接绕过防火墙）  
> **最后更新**：2026-07-22  

---

## 一、设计动机

### 1.1 要解决什么问题

在岗位和能力图谱的应用中，「人」与「岗」之间的匹配是最终价值出口。现有方案存在三个核心瓶颈：

| 问题 | 现状 | Agent 3 的做法 |
|------|------|---------------|
| 简历解析碎片化 | 纯规则/正则无法应对简历格式多样性 | LLM 辅助 NER + 规则兜底，输出结构化 ResumeProfile |
| 匹配不透明 | 传统匹配是黑箱打分，无法解释为什么不匹配 | 基于 NL Profile 的白盒推理，每条匹配结论附证据链 |
| 人岗差异不可操作 | 只给出分数，不给改进方向 | GapAnalyzer 输出缺失技能/经验清单 + 建议 |

### 1.2 设计哲学：延续 NL Profile 白盒范式

延续 Agent2 的 NL Profile 白盒推理范式，确保匹配全流程可解释、可审计、可操作：

```
传统做法：Resume embeddings → Job embeddings → 余弦相似度 → 分数（不可解释）
Agent3 做法：Resume NL Profile + Position NL Profile → LLM 显式推理 → 匹配诊断（可解释、可审计、可操作）
```

## 二、系统架构

### 2.1 六层架构中的位置

```
AI 智能体分析层（紫）
  |-> Agent1: 新岗位发现 + 能力更新
  |-> Agent2: 数据质量治理 + 幻觉防控
  |-> Agent3: 简历解析 + 人岗匹配  <-- 本模块
```

### 2.2 Agent 3 内部模块

```
Agent3Orchestrator (main.py)
├── resume_parser/              简历解析模块
│   ├── FileExtractor           文件提取层（PDF/Word/TXT → 纯文本）
│   ├── SectionSplitter         规则/正则段落分割
│   ├── ResumeParser            LLM + 规则混合 NER 抽取
│   └── schemas.py              ResumeProfile 数据模型
├── job_matching/               人岗匹配模块
│   ├── MatchEngine             三维匹配计算引擎（技能/经验/职责）
│   ├── GapAnalyzer             差距分析器
│   ├── MatchReportBuilder      匹配报告生成器
│   └── schemas.py              MatchReport 数据模型
├── prompt_templates.py         简历解析及匹配场景的 LLM Prompt 模板
├── job_matching/learning_path_generator.py  学习路径规划器（LLM+规则兜底）
├── config.py                   模块配置
└── tests/                      测试套件
```

### 2.3 网络架构：Node.js 桥接

由于 Windows 防火墙/安全软件可能拦截 Python 的 HTTPS 出站连接，系统使用 **Node.js 桥接** 绕过限制：

`
Python (requests/urllib3) → WinError 10013 (被拦截)
    ↓ 自动降级
Node.js (subprocess bridge) → deepseek_bridge.js → HTTPS → DeepSeek API ✓
`

Node.js 桥接位于 gents/agent2/llm/deepseek_bridge.js，Python 通过 subprocess.run() 调用它，传递请求参数为 JSON 文件路径。

### 2.4 数据流

```
用户输入简历文件路径（CLI）
  → FileExtractor → 分段纯文本
  → SectionSplitter + ResumeParser
     → LLM 辅助结构化 → ResumeProfile
     → 存 MongoDB resume_profiles

两种匹配模式：

模式A --position "岗位名"（指定岗位匹配）
  → ProfileStore.get_position_profile_by_name(name)
  → MatchEngine.match(resume, position)
  → GapAnalyzer（含学习路径规划）
     → 对每项差距生成 LearningPath（LLM 5 阶段 / 规则 4 阶段）
  → MatchReport
  → 存 MongoDB match_reports + 打印报告

模式B --match-all（全局最优匹配）
  → ProfileStore.get_all_position_profiles()
  → 遍历计算 match_score，Heap 保留 Top-K
  → 对每个 Top-K 生成 MatchReport
  → 存 MongoDB + 打印排行摘要
```

## 三、模块详解

### 3.1 简历解析模块（resume_parser）

| 组件 | 职责 | 实现方式 |
|------|------|---------|
| FileExtractor | PDF/Word/TXT → 纯文本 | PyMuPDF（fitz）+ python-docx |
| SectionSplitter | 按标题关键词分割段落 | 纯规则正则，离线可用 |
| ResumeParser | 结构化 NER 抽取 | 优先 LLM，降级规则 |

**ResumeProfile 数据结构**：

- **PersonalInfo**：姓名、电话、邮箱、最高学历、工作经验年数、当前职位/公司
- **Education**：学校、学位、专业、起止时间
- **WorkExperience**：公司、职位、起止时间、职责清单、成就清单
- **ProjectExperience**：项目名称、角色、描述、技术栈、亮点
- **skills**：全部技能扁平化列表（LLM 语义归一后）
- **parsing_method**：标识「llm / rule / hybrid」
- **confidence**：整体解析置信度

### 3.2 人岗匹配引擎（job_matching）

**MatchEngine — 三维匹配体系**：

| 维度 | 权重 | 策略 |
|------|------|------|
| 技能匹配 | 0.45 | 候选技能集 vs required_skills / optional_skills 交集+差值；LLM 辅助语义等价归一 |
| 经验匹配 | 0.30 | 工作年限 vs 岗位要求、学历 vs 要求、行业背景 vs 所属领域 |
| 职责匹配 | 0.25 | 候选人工作/项目经历 vs 岗位核心职责关键词覆盖度 |

**两种匹配模式**：

1. **指定岗位匹配**（`--position`）：按岗位名从 `nlp_profiles` 加载对应 PositionProfile，一对一匹配
2. **全局最优匹配**（`--match-all`）：遍历全部 PositionProfile，综合分排序，返回 Top-5

**GapAnalyzer**：

对每项不匹配的必需技能，从 SkillProfile 提取「为什么需要」的解释，输出结构化的差距清单（含重要性、原因、建议）。

**MatchReport 核心字段**：

| 字段 | 说明 |
|------|------|
| overall_match_score | 0-1 综合匹配度（三维加权） |
| dimension_scores | 技能/经验/职责三维评分明细 |
| required_skills_match_rate | 必需技能匹配率 |
| optional_skills_match_rate | 加分技能匹配率 |
| skill_matches | 逐技能匹配结果 + 证据 |
| gaps | 差距清单（含原因+建议） |
| strengths | 候选人优势总结 |
| recommendation | highly_recommend / recommend / consider / not_recommend |
| confidence | 诊断置信度 |
| provenance | 数据溯源（LLM 模型/时间/引用画像） |

## 六、运行说明

### 6.1 前置条件

- Python 3.10+，已安装 PyMuPDF 和 python-docx
- MongoDB 服务运行中（连通 recruitment 数据库）
- DeepSeek API 密钥（可选，未配置时启用规则降级）

### 6.2 环境变量

复用 Agent2 的环境变量配置，无需额外变量。见 `agents/agent2/.env.example`。

### 6.3 运行命令

```bash
# 仅解析简历
python -m agents.agent3.main parse ./简历.pdf

# 解析 + 指定岗位匹配
python -m agents.agent3.main match ./简历.pdf --position "大模型算法工程师"

# 解析 + 全局最优匹配
python -m agents.agent3.main match ./简历.pdf --match-all

# 批量简历解析（预留接口）
# python -m agents.agent3.main batch ./简历目录/
```

### 6.4 运行测试

```bash
cd my
python -m pytest agents/agent3/tests/ -v
```

当前 47 个测试，覆盖：数据模型 10、段落分割 6、规则降级解析 7、匹配引擎 6、差距分析 4、报告生成 6。

### 6.5 输出产物

| MongoDB 集合 | 内容 | 来源 |
|-------------|------|------|
| resume_profiles | 结构化简历画像（ResumeProfile） | resume_parser/ |
| match_reports | 人岗匹配诊断报告（MatchReport） | job_matching/ |

## 八、扩展指南

### 新增文件格式支持

在 `FileExtractor` 中新增提取器方法，实现 `_extract_xxx(file_path) → dict[str, str]` 接口。

### 新增匹配维度

在 `MatchEngine._match_xxx()` 中新增维度计算方法，在配置 `MATCH_WEIGHTS` 中添加权重。

### 调整推荐阈值

在 `config.py` 中修改 `RECOMMEND_HIGH / RECOMMEND_MEDIUM / RECOMMEND_LOW`。

### 自定义 LLM

复用 `agents/agent2/llm/deepseek_client.py` 的接口，或替换为其他 LLM 客户端。
