# Agent 1 使用说明

> **所属项目**：多源异构数据驱动岗位和能力图谱构建与动态演化分析研究
> **所属层级**：AI 智能体分析层
> **核心功能**：新岗位发现 + 能力演化检测

---

## 一、Agent 1 是什么

Agent 1 是系统的岗位发现与能力更新模块。它从清洗后的招聘数据 `jobs_clean` 出发，完成以下两项工作：

1. **新岗位发现**：对招聘数据进行聚类分析，并与已有岗位画像进行对比，自动发现尚未被收录的新兴岗位。
2. **能力演化检测**：分析岗位技能需求的时序变化，检测新增、淘汰、升温和降温的技能。

Agent 1 的输出统一写入 MongoDB 的 `agent1_output` 集合。后续由 Agent 2 进行幻觉防控和结果校验，通过校验后再进入知识图谱。

## 二、安装与配置

### 2.1 环境要求

| 项目                      | 要求                  |
| ----------------------- | ------------------- |
| Python                  | 3.10 及以上            |
| MongoDB                 | 本地或远程实例             |
| DeepSeek API            | 可选，未配置时自动降级到统计模式    |
| `sentence-transformers` | 可选，未安装时自动降级到 TF-IDF |
| `hdbscan`               | 可选，未安装时自动降级到 KMeans |

### 2.2 安装依赖

在项目根目录下执行：

```powershell
cd 项目根目录
pip install -r agents/agent1/requirements.txt
```

### 2.3 配置环境变量

Agent 1 复用 Agent 2 的 `.env` 配置，无需额外添加环境变量。

| 变量                 | 说明              | 默认值                         |
| ------------------ | --------------- | --------------------------- |
| `DEEPSEEK_API_KEY` | DeepSeek API 密钥 | 可选                          |
| `MONGODB_URI`      | MongoDB 连接地址    | `mongodb://localhost:27017` |
| `MONGODB_DB`       | MongoDB 数据库名    | `recruitment`               |

## 三、快速开始

### 3.1 验证安装

在项目根目录下执行：

```powershell
cd 项目根目录
python -m pytest agents/agent1/tests/ -v
```

当 95 个测试全部通过时，说明 Agent 1 安装正确。

### 3.2 运行完整流水线

```powershell
python -m agents.agent1.main
```

完整流水线包含以下两个处理链路：

#### 新岗位发现链路

```text
读取 jobs_clean
→ 招聘数据聚类
→ 新兴性检测
→ LLM 岗位标注
→ 生成新岗位建议
```

#### 能力演化检测链路

```text
读取 jobs_clean
→ 技能趋势分析
→ 能力演化检测
→ 生成技能变更建议
```

所有结果经过统一包装后，写入 MongoDB 的 `agent1_output` 集合。

### 3.3 运行指定模块

#### 仅运行新岗位发现

```powershell
python -m agents.agent1.main --discovery-only
```

#### 仅运行能力演化检测

```powershell
python -m agents.agent1.main --evolution-only
```

#### 指定批次大小

```powershell
python -m agents.agent1.main --batch 200
```

#### 指定行业范围

```powershell
python -m agents.agent1.main --industry "人工智能"
```

## 四、功能详解

### 4.1 新岗位发现

相关代码位于：

```text
job_discovery/
```

处理流程如下：

| 步骤 | 组件                | 作用                                                                      |
| -- | ----------------- | ----------------------------------------------------------------------- |
| 1  | `JobClusterer`    | 对招聘文本进行向量化和聚类，优先使用 SentenceTransformer 和 HDBSCAN，必要时降级到 TF-IDF 和 KMeans |
| 2  | `NoveltyDetector` | 计算招聘数据簇质心与已有 `PositionProfile` 的余弦相似度，判断岗位的新兴程度                         |
| 3  | `LabelGenerator`  | 使用 DeepSeek 自动生成岗位名称、岗位描述和技能要求；未配置 API 时降级到统计规则                         |

#### 新岗位发现阈值

以下参数可在 `config.py` 中调整：

| 参数                          |    默认值 | 说明                            |
| --------------------------- | -----: | ----------------------------- |
| `NOVELTY_THRESHOLD`         | `0.75` | 相似度低于该值时，视为新兴岗位               |
| `NOVELTY_VARIANT_THRESHOLD` | `0.60` | 相似度处于 `0.60～0.75` 时，视为已有岗位的变体 |
| `CLUSTER_MIN_SAMPLES`       |    `5` | 一个有效聚类所需的最小样本数                |

### 4.2 能力演化检测

相关代码位于：

```text
skill_evolution/
```

处理流程如下：

| 步骤 | 组件                   | 作用                         |
| -- | -------------------- | -------------------------- |
| 1  | `SkillTrendAnalyzer` | 按岗位名称分组，并按照时间窗口统计各项技能的出现频次 |
| 2  | `EvolutionDetector`  | 判定技能的四种变化类型，并进行跨领域迁移检测     |

#### 四种技能变化类型

| 类型              | 含义                     | 示例                   |
| --------------- | ---------------------- | -------------------- |
| `new`（新增）       | 过去极少出现，但近期开始频繁出现的技能    | RAG 在 2025 年算法岗位中的出现 |
| `dying`（淘汰）     | 曾经属于常见或必需技能，但近期几乎不再被提及 | Flash 在前端岗位中的淘汰      |
| `rising`（升温）    | 出现频次持续上升的技能            | Kubernetes 在后端岗位中的普及 |
| `declining`（降温） | 出现频次持续下降的技能            | jQuery 在前端岗位中的下降     |

#### 跨领域迁移检测

当一项技能在多个不同岗位中同时呈现升温趋势时，系统会自动将其标记为跨领域热点技能。

### 4.3 三阶段降级策略

| 阶段    | 首选方案                       | 降级方案            |
| ----- | -------------------------- | --------------- |
| 文本向量化 | SentenceTransformer，支持语义理解 | TF-IDF，基于词频统计   |
| 聚类    | HDBSCAN，可自动确定聚类数量          | KMeans，需要指定聚类数量 |
| 新簇标注  | DeepSeek LLM，进行智能命名和描述生成   | 统计规则，提取高频关键词    |

所有降级操作都会自动、静默执行，不需要手动干预，也不会中断处理流程。

## 五、查看结果

### 5.1 MongoDB 输出集合

| 集合              | 内容                     | 记录数参考     |
| --------------- | ---------------------- | --------- |
| `agent1_output` | 新岗位建议和技能变更建议           | 取决于输入数据量  |
| `jobs_kg`       | 经 Agent 2 校验后进入知识图谱的数据 | 主要为高置信度记录 |

每条 `agent1_output` 记录包含以下字段：

| 字段            | 说明                                                  |
| ------------- | --------------------------------------------------- |
| `output_type` | 输出类型，可选值为 `new_position` 或 `skill_change`           |
| `payload`     | 根据 `output_type` 装载对应的业务数据                          |
| `status`      | 处理状态，流转过程为 `pending → verified → rejected / merged` |
| `batch_id`    | 批次标识                                                |
| `created_at`  | 记录创建时间                                              |

### 5.2 使用 MongoDB Compass 查看

1. 打开 MongoDB Compass。

2. 连接到以下地址：

   ```text
   localhost:27017
   ```

3. 选择 `recruitment` 数据库。

4. 点击 `agent1_output` 集合。

### 5.3 使用命令行查看

#### 查看所有输出

```powershell
python -c "import pymongo,json;c=pymongo.MongoClient();d=c['recruitment'];print(json.dumps([{k:v for k,v in r.items() if k not in ('_id',)} for r in d.agent1_output.find()],ensure_ascii=False,indent=2)[:3000]);c.close()"
```

#### 按输出类型统计新岗位数量

```powershell
python -c "import pymongo;c=pymongo.MongoClient();d=c['recruitment'];print(d.agent1_output.count_documents({'output_type':'new_position'}));c.close()"
```

## 七、扩展开发

### 7.1 新增输入字段

在以下文件的 `InputRecord` 中添加字段：

```text
output_adapter/schemas.py
```

系统已经提供 `extras: dict` 字段，可以对未预先定义的输入数据进行兜底存储。

### 7.2 切换聚类算法

可以通过以下两种方式切换或扩展聚类算法：

1. 在 `config.py` 中修改 `CLUSTERING_METHOD`。
2. 在 `JobClusterer` 中新增聚类算法实现。

### 7.3 新增演化检测维度

在 `skill_evolution/` 目录下新建检测器文件，例如：

```text
xxx_detector.py
```

新的检测器需要实现以下接口：

```python
def detect(data) -> list[SkillChangeSuggestion]:
    ...
```

### 7.4 调整阈值

可在 `config.py` 中修改以下参数：

```python
NOVELTY_THRESHOLD = 0.75           # 新兴性判定阈值
TREND_RISING_THRESHOLD = 0.30      # 技能升温判定阈值
TREND_DECLINING_THRESHOLD = -0.30  # 技能降温判定阈值
TREND_MIN_RECORDS = 10             # 趋势分析最低记录数
TREND_WINDOW_MONTHS = 3            # 趋势分析时间窗口，单位为月
```

## 八、注意事项

### 8.1 数据前提

`jobs_clean` 集合应至少包含以下字段：

* `title`
* `description`
* `skills`

进行技能趋势分析时，还必须提供：

* `pub_date`

### 8.2 自动降级

以下依赖或配置缺失时，Agent 1 会自动降级运行：

* 未安装 `sentence-transformers` 时，自动使用 TF-IDF。
* 未安装 `hdbscan` 时，自动使用 KMeans。
* 未配置 DeepSeek API 时，自动使用统计规则进行岗位命名和技能提取。

所有降级均不会中断流水线。

### 8.3 MongoDB 依赖

* 运行完整流水线时，需要能够正常连接 MongoDB。
* 运行单元测试时，不需要 MongoDB。

### 8.4 首次运行耗时

DeepSeek API 的调用次数与聚类数量有关，通常每个有效聚类调用一次。

首次运行预计耗时约为：

```text
30～60 秒
```

实际耗时取决于数据量、聚类数量、网络状况和 API 响应速度。

### 8.5 输出链路

Agent 1 的完整输出链路如下：

```text
jobs_clean
→ Agent 1 分析
→ agent1_output
→ Agent 2 校验
→ jobs_kg
→ Neo4j
```

`agent1_output` 中的记录必须经过 Agent 2 校验后，才能最终写入图数据库。
