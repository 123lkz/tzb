# Agent 2 使用说明

> 所属项目：多源异构数据驱动岗位和能力图谱构建与动态演化分析研究  
> 所属层级：AI 智能体分析层  
> 核心功能：数据质量治理 + 基于自然语言画像的幻觉防控  

---

## 一、Agent 2 是什么

Agent 2 是系统的数据质量与知识可信度保障模块。它从清洗后的招聘数据（`jobs_clean`）出发，做三件事：

1. **数据质量检查**：对每条招聘记录检查字段完整性、一致性、时效性、抄袭和噪声
2. **构建自然语言画像**：为每个技能和岗位生成可读、可审计的结构化自然语言描述
3. **幻觉防控**：对每对技能-岗位关系进行白盒推理验证，替代传统黑箱 embedding 方法

## 二、安装与配置

### 2.1 环境要求

| 项目 | 要求 |
|------|------|
| Python | 3.10+ |
| MongoDB | 本地或远程实例（推荐 7.0+）|
| DeepSeek API | 可选（未配置时自动使用模拟模式）|

### 2.2 安装

```
cd 项目根目录
pip install -r agents/agent2/requirements.txt
```

### 2.3 配置

在项目根目录或 `agents/agent2/` 目录下创建 `.env` 文件：

```
# DeepSeek API（可选）
XF_API_KEY=your_api_key
XF_API_SECRET=your_api_secret
XF_APP_ID=your_app_id
XF_API_BASE=wss://spark-api.xf-yun.com/v4.0/chat
XF_MODEL=deepseek-chat

# MongoDB（未配置时默认 mongodb://localhost:27017/recruitment）
MONGODB_URI=mongodb://localhost:27017
MONGODB_DB=recruitment

# 日志
LOG_LEVEL=INFO
```

也可以直接复制模板文件：

```
cp agents/agent2/.env.example agents/agent2/.env
```

## 三、快速开始

### 3.1 验证安装

```
cd 项目根目录
python -m pytest agents/agent2/tests/ -v
```

40 个测试全部通过即安装正确。

### 3.2 运行完整流水线

```
python -m agents.agent2.main
```

执行三条流程：
1. 读取 MongoDB.jobs_clean -> 数据质量检查 -> 写 quality_reports
2. 提取技能和岗位 -> 生成自然语言画像 -> 写 nlp_profiles
3. 对每对技能-岗位做白盒验证 -> 写 relation_profiles + audit_queue + jobs_kg

### 3.3 运行指定模块

```
# 仅运行数据质量检查
python -m agents.agent2.main --check-only

# 仅构建自然语言画像
python -m agents.agent2.main --profile-only

# 仅运行幻觉防控
python -m agents.agent2.main --hallucination-only

# 指定处理批次大小
python -m agents.agent2.main --batch 200
```

---


### 3.4 运行去重

`ash
python -m agents.agent2.main --dedup
`

去重分三个阶段：
1. 精确去重：移除 title+company+city 完全一致的重复记录
2. 跨平台去重：合并同一岗位在不同招聘平台的数据
3. 内容去重：合并不同公司但相同岗位且 JD 描述高度相似的记录


## 四、功能详解

### 4.1 数据质量检查（data_quality/）

对 jobs_clean 中的每条记录，依次执行 5 个内置检查器：

| 检查器 | 检查内容 | 触发条件示例 |
|--------|---------|-------------|
| Completeness | 必填字段是否完整 | 缺少 title/company/salary/skills/city |
| Consistency | 薪资与经验/学历是否自洽 | 应届生标注超高薪资（>30K）|
| Timeliness | 发布时间是否过久、技能是否过时 | 发布于 180 天前；含 Flash/jQuery |
| Plagiarism | JD 文本是否高度模板化 | 检测到大量通用模板短语 |
| NoiseDetector | 异常薪资、公司名异常、技能-岗位不匹配 | 薪资<3K 或 >500K；会计岗要求 PyTorch |

**输出**：每条记录生成一份 QualityReport，包含综合评分和各检查器的明细。

### 4.2 自然语言画像系统（nlp_profile/）

将技能和岗位表示为结构化自然语言文档：

**技能画像（SkillProfile）**示例：

| 字段 | 内容 |
|------|------|
| name | PyTorch |
| summary | PyTorch 是由 Meta 开源的深度学习框架，以动态计算图和灵活构建能力著称 |
| prerequisites | Python、线性代数与概率统计、深度学习基础 |
| related_technologies | Transformer、CUDA、HuggingFace、DeepSpeed、ONNX |
| typical_applications | 大规模语言模型、计算机视觉、自然语言处理、生成式 AI |

**岗位画像（PositionProfile）**示例：

| 字段 | 内容 |
|------|------|
| name | 大模型算法工程师 |
| summary | 专注于大规模语言模型全生命周期研发 |
| required_skills | 精通 PyTorch 框架、熟悉分布式训练、掌握推理加速技术 |
| core_responsibilities | 模型训练与迭代优化、微调适配、部署优化 |

**关系画像（RelationProfile）**示例：

| 字段 | 内容 |
|------|------|
| source | PyTorch（技能）|
| target | 大模型算法工程师（岗位）|
| valid | True |
| confidence | 0.805 |
| explanation | 大模型算法工程师的核心职责包括大规模语言模型的训练微调，这些工作均需依托深度学习框架实现 |

### 4.3 幻觉防控（hallucination_prevention/）

这是 Agent 2 的核心创新。验证逻辑：

```
SkillProfile.summary + PositionProfile.summary
  -> LLM 阅读两段自然语言描述
  -> 显式推理："该技能是否被该岗位合理需要？"
  -> 输出：(valid, confidence, explanation)
```

**3 轮共识机制**：每次验证执行 3 轮独立推理，多数投票 + 方差调整，避免单次幻觉。

**4 维置信度评分**：

| 维度 | 权重 | 说明 |
|------|------|------|
| LLM 置信度 | 0.40 | LLM 直接输出的置信度 |
| 证据强度 | 0.30 | 支持证据的数量和质量 |
| 解释质量 | 0.15 | 推理文本长度和详细程度 |
| 来源多样性 | 0.15 | 数据来源平台的多样性 |

**分级处理**：

| 置信度 | 处理方式 |
|--------|---------|
| >= 0.85 且 valid=True | 直接写入 jobs_kg（最终入图）|
| < 0.60 或 valid=False | 入 audit_queue（等待人工审核）|
| 其余 | 写 relation_profiles 标记待观察 |

## 六、扩展开发

### 6.1 新增数据质量检查器

在 data_quality/builtin/ 下新建文件，继承 AbstractDataQualityChecker：

```
from agents.agent2.data_quality.base_checker import (
    AbstractDataQualityChecker, CheckResult, CheckerType,
)

class MyChecker(AbstractDataQualityChecker):
    @property
    def name(self) -> str: return "my_checker"

    def check(self, record: dict) -> CheckResult:
        passed = True; score = 1.0
        return CheckResult(
            checker_name=self.name, passed=passed, score=score,
            details="My check passed", flagged_items=[],
        )
```

注册自动通过 __init_subclass__ 完成，无需手动注册。

### 6.2 切换 LLM 模型

修改 config.py 中的配置，或传入自定义 LLM 客户端（需实现 chat(messages, temperature) -> str 接口）。

### 6.3 调整阈值

在 config.py 中修改：

```
CONFIDENCE_HIGH_THRESHOLD = 0.85   # >= 此值直接入 jobs_kg
CONFIDENCE_MEDIUM_THRESHOLD = 0.60 # >= 此值标记待观察
CONFIDENCE_LOW_THRESHOLD = 0.30    # < 此值直接过滤
CONSENSUS_MIN_ROUNDS = 3           # 共识推理轮次
DEFAULT_BATCH_SIZE = 50            # 每批次处理记录数
```

## 七、注意事项

1. **数据前提**：jobs_clean 集合必须已包含清洗后的招聘数据，字段应包含 title、company、salary、skills、city、description 等
2. **LLM 降级策略**：未配置或连接失败时自动使用模拟模式（mock），不会因此报错中断
3. **MongoDB 依赖**：运行流水线需要 MongoDB 连接可用；运行单元测试不需要
4. **首次运行耗时**：LLM 调用较多（约 20+ 次），首次运行约 30-60 秒
5. **人工审核**：audit_queue 中的记录需要人工确认后才能最终入图数据库
