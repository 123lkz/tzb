### 5.1 功能概览

- 多字段过滤查询：关键词、行业、地点、学历、经验、薪资
- 排序控制：薪资从高到低 / 从低到高、招聘人数、发布时间

### 5.2 技术架构

过滤参数 (reactive) computed filterPositions()
  - 岗位列表 (filteredPositions) → 卡片网格
  - 统计数据 (statCards) → 3 张统计卡片
  - 分页数据 (currentPageItems) → 分页控件

过滤选项从 jobs_clean 数据动态提取，非硬编码。

### 5.3 设计思路

- 采用“过滤栏 + 列表”的经典 CRUD 布局
- 服务端渲染首页数据，客户端变更过滤参数时全前端 computed 响应
- 卡片展示信息密集但有序，适合扫描式浏览
- 当前采用纯前端过滤，未来接入后端时切换为 useFetch + watch

## 7. 模块四：能力洞察

路由：/insights  文件：pages/insights.vue (248行)

### 7.1 功能概览

- 5 张数据概览卡片：岗位画像、技能总数、新发现、待审核、质量评分
- 触发新岗位分析按钮，位于页面右侧
- 左侧：技能趋势分析图表（ECharts 折线图，支持下拉切换岗位）
- 右侧：新发现岗位列表（可滚动容器 + 确认/忽略按钮）
- 待审核弹窗（点击“待审核”卡片打开，支持“通过”“跳过”）

### 7.2 新岗位发现说明

新岗位发现是本页面的核心功能，由 Agent1 的 job_discovery 管线驱动。

**触发流程：**
1. 用户点击“触发新岗位分析”按钮
2. 前端调用 POST /api/insights/run-discovery
3. 后端启动 Agent1 整个管线：job_clusterer → novelty_detector → label_generator → change_record_builder
4. 分析结果写入 agent1_output 集合，关键字段包含：suggested_name、description、suggested_required_skills、suggested_optional_skills、core_responsibilities、typical_applications、cluster_size、novelty_score等
5. 前端刷新概览数据，新岗位以卡片形式展示在右侧

**确认/忽略机制：**
- “确认”：调用 POST /api/insights/new-positions/confirm，将该新岗位的 status 更新为 confirmed，后续可写入 nlp_profiles 作为正式岗位画像
- “忽略”：调用 POST /api/insights/new-positions/dismiss，status 更新为 dismissed，数据保留但不再显示在待处理列表中
- 前端即时更新本地状态，无需等待后端回调

**岗位卡片展示信息：**
- 岗位名称、置信度、当前状态（pending / confirmed / dismissed）
- 核心职责、必备技能、加分技能、典型应用场景
- 确认/忽略按钮（仅 pending 状态可见）

### 7.3 技能趋势分析设计思路（待确认）

**当前状态：模拟数据阶段**

技能趋势分析目前使用的是前端内置的模拟数据（在 fetchSkillTrend() 的回退逻辑中），原因是真实的时序数据依赖于 Agent1 的 skill_evolution 模块完整接入。

当前模拟数据结构：

```json
{
  periods: ["2025-Q1","2025-Q2","2025-Q3","2025-Q4","2026-Q1","2026-Q2"],
  skills: {
    Python: { frequency: [65,70,72,75,78,82], change: "rising", pct: "+12%" },
    PyTorch: { frequency: [40,45,50,55,58,60], change: "rising", pct: "+8%" },
    RAG: { frequency: [0,0,2,8,15,25], change: "new", pct: "新增" }
  }
}
```

**接入真实数据的设计思路：**

真实数据将由 Agent1 的 SkillTrendAnalyzer 生成，其核心逻辑如下：

1. 从 jobs_clean 读取同类岗位的全部记录
2. 按照 pub_date 将数据划分为季度时间窗口（2025-Q1 → 2026-Q4）
3. 统计每个时间窗口内各技能的出现频率（frequency）
4. 判断技能变化趋势：上升、下降、新增、稳定、衰退
5. 返回结构化数据给前端渲染

**数据依赖前提：**
- 岗位数据必须包含 pub_date 字段（已在爬虫数据交接文档中明确为必填）
- 每个岗位类型至少需要跨越 2-3 个季度的数据才能有意义
- Agent1 需要完整运行一次 pipeline 才能生成趋势数据

**前端迁移计划：**
1. 当前阶段：全部使用模拟数据，用于 UI 验证和样式调整
2. 过渡阶段：前端先调用 API，若返回的数据不符合预期格式则回退到模拟数据
3. 完整阶段：彻底移除模拟数据，完全依赖后端 API

**图表渲染技术细节：**
- ECharts 采用动态 import() 延迟加载，不影响 SSR 首屏速度
- 每条线代表一个技能，显示前 5 个最高频率的技能
- 线条颜色根据变化趋势区分：新增=#6bcb77、上升=#00ffff、下降=#ffd93d、稳定=#546e7a、衰退=#ff6b6b
- 图表底部显示小标签，标注每个技能的变化百分比

### 7.4 待审核功能说明

待审核功能是岗位与技能关系画像的人工审核机制。Agent2 在关系挖掘时会生成大量关系画像，其中低置信度的进入 audit_queue 集合，等待人工审核。

**触发方式：**
- 点击概览卡片中的“待审核”卡片（显示待审数量）
- 弹出模态框，显示 audit_queue 中的所有待审项

**数据来源：**
- API: GET /api/insights/audit-queue
- 集合：recruitment.audit_queue
- 每条记录包含：targetName（岗位名称）、sourceName（技能名称）、confidence（置信度）、explanation（推理说明）
- 更详细的字段（如 evidence、counter_evidence）可参考 relation_profiles 集合

**审核操作：**
- “通过”：调用 POST /api/insights/audit-queue/approve?id=<id>，将该条关系画像写入 jobs_kg 集合，并从 audit_queue 中删除
- “跳过”：仅在前端本地过滤排除，数据保留在 audit_queue 中不动
- 每次操作后前端即时更新列表，同步更新概览卡片中的待审核数量

**判断标准参考：**
- 当前主要判断“某技能是否应属于某岗位”
- 高置信度（>= 0.85）的关系自动写入 relation_profiles
- 低置信度（< 0.85）的关系进入 audit_queue 等待人工审核
- 审核通过后写入 jobs_kg，作为知识图谱的基础关系数据

### 7.5 其他设计思路

- 新岗位列表用 max-h-[360px] + overflow-y-auto 限制高度，避免占据整个右侧视屏
- 待审核弹窗使用 <Teleport to=\body> 避免嵌套容器问题
- 函数命名规范：前缀 handle/do 表示用户触发的操作
- 概览数据来源于后端 /api/insights/overview，回退时使用前端内置 mock

## 9. 数据层与 API 调用机制

### 9.1 两层数据架构

utils/api.ts — API 调用层
  - callApi(endpoint)  # 核心请求函数，15s 超时
  - 类型分层:
    - 公用 API: fetchPositions, fetchGraphData
    - Agent3 API: parseResume, matchPosition, matchAll
    - Insights API: fetchOverview, fetchSkillTrend, runDiscovery
  - 回退机制: API 失败时自动切换到 mockData

utils/mockData.ts — 模拟数据层
  - mockPositions (20 条)
  - mockResume、mockGraphData
  - generateMockReport()、filterPositions()

### 9.2 API 调用流程

1. 先尝试调用 http://localhost:8720/api/<endpoint>
2. 超时或服务端错误时自动回退到 mock
3. USE_BACKEND 变量控制是否尝试后端
4. AbortSignal.timeout(15000) 保证请求不挂起

### 9.3 后端接口概览

| 接口 | 方法 | 用途 | 模块 |

| /api/match-position | POST | 指定岗位匹配 | 简历匹配 |
| /api/match-all | POST | 全局匹配 | 简历匹配 |
| /api/insights/overview | GET | 能力洞察概览 | 能力洞察 |
| /api/insights/skills-trend | GET | 技能趋势 | 能力洞察 |
| /api/insights/run-discovery | POST | 新岗位分析 | 能力洞察 |
