# 数据交接文档 — 爬虫数据入库规范

## 1. 概述

本文档面向爬虫项目组，说明爬取的岗位数据需要以何种格式写入数据库，以便后续系统（后端 API、Agent 分析引擎、前端展示）能够正常使用。

**项目名称**：新一代信息技术岗位全景图谱 — 人岗匹配平台
**对接系统**：后端 FastAPI 服务（`backend/server.py`）
**数据库**：MongoDB（本地实例，默认端口 27017）

---

## 2. 数据库配置

| 项目 | 值 |
|---|---|
| 数据库类型 | MongoDB |
| 连接地址 | `mongodb://localhost:27017/` |
| 数据库名称 | `recruitment` |
| 主要写入集合 | **`jobs_clean`** |
| 字符编码 | UTF-8 |

爬虫程序只需向 **`recruitment.jobs_clean`** 集合写入清洗后的岗位数据即可。其他集合（如 `jobs_deduplicated`、`nlp_profiles`、`agent1_output`、`audit_queue`、`match_reports` 等）由后端和 Agent 模块自动生成，无需爬虫关注。

---

## 3. jobs_clean 文档结构

`jobs_clean` 是爬虫数据入库的**唯一目标集合**，每条记录代表一个岗位。

### 3.1 字段定义

| 字段名 | 类型 | 必填 | 说明 | 示例 |
|---|---|---|---|---|
| `_id` | ObjectId | 自动 | MongoDB 自动生成，无需传入 | — |
| **`title`** | string | **是** | 岗位名称 | `"数据分析师"` |
| **`company`** | string | **是** | 招聘公司名称 | `"美团"` |
| **`salary`** | string | **是** | 薪资范围，格式 `"最低K-最高K"` | `"28K-116K"` |
| **`skills`** | string[] | **是** | 技能标签列表 | `["SQL","Pandas","Excel"]` |
| **`city`** | string | **是** | 工作城市 | `"西安"` |
| **`experience`** | string | **是** | 经验要求 | `"1-3年"` |
| **`education`** | string | **是** | 学历要求 | `"本科"` |
| **`source`** | string | **是** | 数据来源平台 | `"bosszhipin"` |
| **`description`** | string | **是** | 岗位描述文本 | `"负责核心模块开发……"` |
| **`pub_date`** | string | **是** | 发布日期，格式 `"YYYY-MM-DD"` | `"2026-05-20"` |


### 3.2 发布时间要求

`pub_date` 是能力洞察界面“技能趋势分析”的关键字段。Agent1 会根据岗位发布时间划分时间窗口，分析技能需求的浮动与衰减趋势。因此爬虫需要注意：

- **必填**：每条岗位记录必须具有 `pub_date` 字段，缺失则跳过。
- **爬取策略**：建议按照季度爬取，关注近两年的数据。
  - 推荐时间范围：2025-Q3 → 2026-Q2
  - 每个季度至少爬取 20 条以上同类岗位数据

## 4. 数据清洗要求

爬虫在写入 `jobs_clean` 前需确保以下清洗规则：

### 4.1 必做清洗

1. **去重**：同一平台+同一岗位名称+同一公司+同一城市 视为重复，仅保留一条。
2. **薪资格式统一**：转换为 `"最低K-最高K"` 格式，均以 K（千元/月）为单位。
   - `"15k-25k"` → `"15K-25K"`
   - `"15000-25000/月"` → `"15K-25K"`
   - `"面议"` → 建议跳过该条或标记为 `"0K-0K"`
3. **技能列表清洗**：`skills` 为字符串数组，去除空值和前后空格，统一首字母大小写。
4. **字段去空**：`title`、`company`、`salary`、`skills`、`city`、`experience`、`education`、`source`、`pub_date` 至少有一项为空则跳过该条记录。
5. **日期格式**：`pub_date` 统一为 `YYYY-MM-DD` 格式。

### 4.2 建议做

- 对 `description` 做简单的文本清洗（去除 HTML 标签、多余空白符、特殊字符）。
- 如果爬取到多个来源的同一岗位（不同平台），暂时保留所有记录，后续去重由 Agent2 处理。

## 5. 后端数据映射（不用看）

后端在 `/api/positions` 接口中从 `jobs_clean` 读取数据后，会进行字段映射以适配前端展示：

| jobs_clean 字段 | 映射后字段 | 转换逻辑 |
|---|---|---|
| `title` | `name` | 直接映射 |
| `company` | `company` | 直接映射 |
| `salary` | `salaryMin` / `salaryMax` | `_parse_salary()` 拆分为数值 |
| `skills` | `requiredSkills` | 直接映射 |
| `city` | `city` / `province` | 通过 `_infer_province()` 推断省份 |
| `skills` | `industry` | 通过 `_infer_industry()` 推断行业 |
| `education` | `education` | 直接映射 |
| `experience` | `experience` | 直接映射 |
| `pub_date` | `publishDate` | 直接映射 |
| `source` | `platform` | 直接映射 |

爬虫可自愿补充 `responsibilities`（职责列表）和 `positionUrl`（岗位链接）字段，后端会透传到前端。

## 6. 其他集合说明（不用看）

| 集合名称 | 用途 | 写入方 |
|---|---|---|
| `jobs_clean` | 爬虫清洗后的原始岗位数据 | **爬虫** |

| `jobs_kg` | 已审核通过的知识图谱关系数据 | 人工审核后写入 |
| `resume_profiles` | 简历解析结果 | Agent3 |
| `match_reports` | 岗位匹配报告 | Agent3 |
| `quality_reports` | 数据质量评估报告 | Agent2 |

## 7. 注意事项（不用看）

1. **写入频率**：后端服务在启动时读取 `jobs_clean` 并提供查询 API，写入后可立即生效。建议使用 `insert_many` 批量写入。
2. **数据量上限**：当前 `jobs_clean` 数据量为 100 条。后端 `list_positions` 接口限制最大返回 200 条。若数据量大幅增长，需后端配合调整分页逻辑。
3. **Agent 依赖**：Agent2 会从 `jobs_clean` 读取数据并写入 `jobs_deduplicated`、`nlp_profiles`、`audit_queue`。爬虫无需关心这些衍生集合。
4. **字段扩展**：如需新增字段，请与后端开发沟通，确保 API 层兼容处理。

## 8. 快速验证（不用看）

爬虫写入数据后，可通过以下方式验证：

```bash
# 1. 确认集合中有数据
mongosh recruitment --eval "db.jobs_clean.countDocuments()"

# 2. 查看最新写入的 5 条记录
mongosh recruitment --eval "db.jobs_clean.find().limit(5).pretty()"

# 3. 检查后端 API 是否正常返回
curl http://localhost:8720/api/positions
```
